---
title: "卸载 Hanamori"
description: "删除当前程序，或额外清理所选管理器拥有的数据。"
icon: PackageMinus
---

```sh
hanamori self uninstall --dry-run
hanamori self uninstall
hanamori --manager-dir D:/Tools/Hanamori self uninstall --purge --dry-run
hanamori --manager-dir D:/Tools/Hanamori self uninstall --purge
```

默认删除当前正在运行的程序、同级 `.outdated` 升级备份和已记录且仍可确认归属的启动入口。MSVC、SDK、配置和命名引用保留，以便之后重新放入程序继续管理。程序位于 Downloads 时，不会递归删除 Downloads。

`--purge` 额外删除当前 `toolchains_dir` 下发现的托管工具链，包括不完整的目录；清理配置指定缓存的完整负载，最后删除命名引用与 `config.json`。外部导入或 `install --dir` 创建的目录只移除引用，实体文件不删除。若多个管理器配置为同一个工具链存储目录，它们共享这些实体目录；清理也会影响它们。共享缓存可能失去完整负载，与 `cache clean` 相同。

未知文件、下载工作区、profile 备份和锁文件（包括 `.update.lock`）保留；剩余目录不递归清空。托管目录整体删除，不要把需要保留的文件放入其中。若程序或管理器位于待删除的工具链中，先移到外部。

## 启动入口与会话

先 `hanamori deactivate`，并关闭其他使用 Hanamori 的终端。新的 `shell init` 将实际入口写入用户数据目录的 `Hanamori/shell/registrations`；Windows 使用 LOCALAPPDATA，Unix 使用 XDG_DATA_HOME 或 `~/.local/share`。Bash 登录桥接和 CMD 辅助脚本也记录在内。

卸载核对区块内容、profile 位置或 CMD loader 归属；修改过的入口会保留并提示。旧版本或手工添加的入口没有记录，需要手动清理，或先以相同 profile/运行时选项重新初始化。手动加入的 PATH、Windows 卸载注册表项不会被修改。重开终端才会丢弃已加载的函数。

## 失败后如何处理

工具链或缓存清理失败时，停止删除程序和剩余管理器元数据；先前已完成的卸载不回滚。关闭占用文件的程序并按错误提示处理后重试；不完整的托管目录仍可再次卸载。预览不写文件、改注册表、取锁或启动辅助进程。

Windows 最后启动临时 PowerShell 脚本，等待主进程退出后删除精确程序路径和备份，不终止其他进程。CLI 报告“已安排”，辅助脚本另行报告结果。删除失败时，在显示的临时目录保留 `failure.txt`、`files.json`、`uninstall.ps1`；关闭占用进程后，不带参数重新运行脚本。成功后删除辅助文件和空临时目录。

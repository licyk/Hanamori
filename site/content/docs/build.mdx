## 一键安装

在 Windows x64 / ARM64 的 PowerShell 5.1 或 PowerShell 7 中运行：

```powershell
irm https://hanamori.netlify.app/install.ps1 | iex
```

默认下载最新稳定版，验证 SHA-256、大小和程序版本后，安装到 `%LOCALAPPDATA%\Hanamori\bin\hanamori.exe`，配置用户 PATH、当前 PowerShell 的启动 Hook 与补全。无需管理员权限，也不下载工具链。命令直接在当前 PowerShell 执行时立即生效；从子进程执行安装后需要打开新终端。

指定版本或安装目录时，将脚本作为带参数的脚本块执行：

```powershell
& ([scriptblock]::Create((irm https://hanamori.netlify.app/install.ps1))) -Version 0.1.0 -InstallDir 'D:\Tools\Hanamori'
```

也可以通过 `HANAMORI_INSTALL_DIR` 设置存放 `hanamori.exe` 的目录：

```powershell
$env:HANAMORI_INSTALL_DIR = 'D:\Tools\Hanamori'
irm https://hanamori.netlify.app/install.ps1 | iex
```

安装路径优先级为 `-InstallDir` → `HANAMORI_INSTALL_DIR` → `%LOCALAPPDATA%\Hanamori\bin`。环境变量未设置或为空时使用默认目录。

| 参数 | 含义 |
| --- | --- |
| `-Version` | `latest` 或指定版本，可带 `v` 前缀 |
| `-InstallDir` | 存放 `hanamori.exe` 的目录 |
| `-NoPathUpdate` | 跳过用户和当前进程 PATH 配置 |
| `-NoShell` | 跳过当前 PowerShell 的持久与会话集成 |

重复运行会替换程序并复用已有配置；下载或验证失败时保留旧程序。`HANAMORI_HOME` 仍控制管理器数据目录，不控制程序安装目录。脚本保留原有 PATH 和 Profile 内容，不修改执行策略；受策略限制的 Profile 会给出提示。其他 Shell 可按 [Shell 集成](/docs/shell) 配置。

安装完成后按需运行 `hanamori install latest --name stable` 安装工具链。之后使用 `hanamori upgrade` 更新本体，使用 `hanamori self uninstall` 卸载。卸载命令会根据程序旁的 `.install.json` 记录清理脚本添加的 PATH 条目。

## MSYS2 与 Git Bash

在 Windows x64 / ARM64 的 MSYS2 或 Git Bash 中运行：

```bash
curl -fsSL https://hanamori.netlify.app/install.sh | bash
```

脚本复用 PowerShell 安装器下载和验证程序、配置用户 PATH，并通过 `hanamori shell init --shell bash` 为实际运行脚本的 Bash 配置 `.bashrc`、登录入口与补全。默认安装目录为 `%LOCALAPPDATA%\Hanamori\bin`，不下载工具链，也不修改 PowerShell Profile。

需要 `cygpath`、`curl` 和 Windows PowerShell 或 PowerShell 7。MSYS2 未将 PowerShell 加入 PATH 时，会从 Windows 系统目录查找。仓库内可直接运行 `bash install.sh`，使用同目录的 `install.ps1`。

```bash
curl -fsSL https://hanamori.netlify.app/install.sh | bash -s -- \
  --version 0.1.0 --install-dir '/c/Tools/Hanamori'
```

参数为 `--version`、`--install-dir`、`--no-path-update` 和 `--no-shell`；安装目录支持 MSYS 路径和 Windows 路径。`--no-shell` 跳过 Bash 启动文件与补全配置，`--no-path-update` 跳过用户 PATH 配置。

Bash 同样支持 `HANAMORI_INSTALL_DIR`，`--install-dir` 优先于环境变量。变量未设置或为空时使用默认目录；管道安装时将变量传给 `bash`：

```bash
curl -fsSL https://hanamori.netlify.app/install.sh | HANAMORI_INSTALL_DIR='/d/Tools/Hanamori' bash
```

`curl | bash` 运行在子进程中。安装后重开 Bash，或执行脚本输出的 Hook 加载命令，让当前终端立即使用 Hanamori。MSYS2 启动时可能重新组织 PATH；Bash Hook 通过程序的绝对路径调用 Hanamori。

## 便携安装

首先查看[下载页](/download)。发布流程为 x64 和 ARM64 分别提供 EXE 与 ZIP：`hanamori-x86_64-pc-windows-msvc.*` 与 `hanamori-aarch64-pc-windows-msvc.*`，ZIP 内的程序为 `hanamori.exe`。直接下载 EXE 后可以改名为 `hanamori.exe`。

将程序放在自己的工具目录，例如 `D:\Tools\Hanamori`。临时在 PowerShell 添加 PATH：

```powershell
$env:PATH = "D:\Tools\Hanamori;$env:PATH"
hanamori --version
hanamori --help
```

需要持久 PATH 时，在 Windows 的用户环境变量设置中加入该目录，然后重开终端。`shell init` 配置启动钩子，不负责给系统 PATH 安装程序。程序是便携的，不需要 Visual Studio、aria2c 或 msiexec 来运行安装器。

## 从源码构建

构建需要 Rust 工具链以及对应目标的链接器和构建依赖；运行已构建的安装器不需要 Rust。

```sh
git clone https://github.com/licyk/Hanamori.git
cd Hanamori
cargo build --locked --release -p hanamori --bin hanamori
```

Windows 上输出为 `target/release/hanamori.exe`。发行流程使用 `x86_64-pc-windows-msvc` / `aarch64-pc-windows-msvc` 目标，输出在 `target/<目标>/release/`。程序自我更新支持这两个目标；GNU 或 Unix 构建不会获得该更新资产。开发与验收见[架构](/docs/architecture)、[测试](/docs/testing)和[发布流程](/docs/release)。

## ARM64 程序版本

安装脚本根据 Windows 原生架构选择程序，即使从仿真 Shell 启动也是如此。PowerShell 可用 `-Architecture x64` / `-Architecture arm64`，Bash 可用 `--architecture x64` / `--architecture arm64` 覆盖。该参数选择 Hanamori 本身；`hanamori install --arch HOST/TARGET` 独立选择编译工具链。

ARM64 发布包含 `hanamori-aarch64-pc-windows-msvc.exe` 和 `.zip`，ZIP 内为 `hanamori.exe`。源码构建使用 `cargo build --release --target aarch64-pc-windows-msvc`，并准备相应的 MSVC 链接器。
